# Plan: `temporalio.local_server.LocalServer`

## Problem

The SDK can download and run a local Temporal dev server, but this capability is buried inside
`temporalio.testing.WorkflowEnvironment.start_local()` — a test-specific API that couples server
lifecycle to a `WorkflowEnvironment` and adds test-only interceptors (`_AssertionErrorInterceptor`).
Users who just want to run a local server for development (not testing) have no clean way to do so
from Python.

## Key requirements

1. **Class `LocalServer`** in `temporalio.local_server` with the same server-lifecycle parameters as
   `WorkflowEnvironment.start_local()` (minus client-connection parameters like `data_converter`,
   `interceptors`, `plugins`, etc.).
2. **Async context manager**: `async with LocalServer(...) as server:` — starts on enter, shuts
   down on exit.
3. **Explicit lifecycle**: `server = LocalServer(...); await server.start(); ... await server.shutdown()`.
4. **`target` property**: exposes the frontend address (e.g. `127.0.0.1:7233`) so users can
   connect a `Client` to it.
5. **Share code** with `WorkflowEnvironment.start_local()` — refactor so both use the same
   underlying logic.

## Design

### `LocalServer` — what it is and isn't

`LocalServer` is a thin, user-facing wrapper around the bridge-level `EphemeralServer` with
`start_dev_server`. It owns exactly the server-lifecycle concern: download-if-needed, start, expose
target address, shutdown. It does **not** create a `Client` or add interceptors — that's the
caller's job.

### API

```python
class LocalServer:
    def __init__(
        self,
        *,
        namespace: str = "default",
        ip: str = "127.0.0.1",
        port: int | None = None,
        download_dest_dir: str | None = None,
        ui: bool = False,
        runtime: temporalio.runtime.Runtime | None = None,
        search_attributes: Sequence[temporalio.common.SearchAttributeKey] = (),
        dev_server_existing_path: str | None = None,
        dev_server_database_filename: str | None = None,
        dev_server_log_format: str = "pretty",
        dev_server_log_level: str | None = "warn",
        dev_server_download_version: str = "default",
        dev_server_extra_args: Sequence[str] = [],
        dev_server_download_ttl: timedelta | None = None,
        ui_port: int | None = None,
    ) -> None: ...

    async def start(self) -> None: ...

    async def shutdown(self) -> None: ...

    @property
    def target(self) -> str: ...

    async def __aenter__(self) -> Self: ...

    async def __aexit__(self, *args) -> None: ...
```

Constructor stores config; `start()` does the actual download/launch; `shutdown()` tears it down.
The context manager calls `start`/`shutdown`. Calling `start()` twice or `shutdown()` before
`start()` raises `RuntimeError`.

### Sharing code with `WorkflowEnvironment.start_local()`

The server-startup logic (log-level translation, search-attribute arg construction, building
`DevServerConfig`, calling `EphemeralServer.start_dev_server`) will live in `LocalServer.start()`.
`WorkflowEnvironment.start_local()` will be refactored to use `LocalServer` internally: it creates
a `LocalServer`, starts it, then connects a `Client` to `server.target`.

## Components to create/update

### 1. New file: `temporalio/local_server.py`

Contains the `LocalServer` class. The implementation extracts the server-startup logic currently
in `WorkflowEnvironment.start_local()` (lines 160–205 of `temporalio/testing/_workflow.py`):
log-level translation, search-attribute extra-args construction, `DevServerConfig` assembly,
`EphemeralServer.start_dev_server()` call.

### 2. Update: `temporalio/testing/_workflow.py`

Refactor `WorkflowEnvironment.start_local()` to:
1. Create a `LocalServer` with the server-lifecycle params.
2. `await server.start()`
3. Connect a `Client` to `server.target`.
4. On connection failure, `await server.shutdown()` (as today).
5. Return `_EphemeralServerWorkflowEnvironment(client, server._server)` (using the bridge-level
   `EphemeralServer` from the `LocalServer` instance).

### 3. Update: `temporalio/__init__.py`

No changes needed — `local_server` is a submodule that users import explicitly.

### 4. Tests

- **Unit-level test** for `LocalServer`: start via context manager, verify `target` is a valid
  address, connect a client, do a basic operation (e.g. list namespaces or describe namespace),
  verify shutdown is clean.
- **Explicit lifecycle test**: `start()` then `shutdown()` without context manager.
- **Error tests**: calling `start()` twice raises `RuntimeError`; calling `shutdown()` before
  `start()` raises `RuntimeError`.
- Verify existing `WorkflowEnvironment.start_local()` tests still pass (no behavioral change).

## Execution order

1. Create `temporalio/local_server.py` with `LocalServer`.
2. Refactor `WorkflowEnvironment.start_local()` to use `LocalServer`.
3. Run existing tests to confirm no regressions.
4. Write new tests for `LocalServer`.
5. Run all linting/formatting/type-checking.

## How to verify

Run the new tests:
```
uv run pytest tests/test_local_server.py -v
```

Run the existing test-environment tests to confirm no regressions:
```
uv run pytest tests/test_testing.py -v
```

The new `LocalServer` tests should fail if `LocalServer` is removed or broken; the existing
`WorkflowEnvironment.start_local()` tests should continue to pass unchanged.
